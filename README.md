# TaskFlow

A calm, fast task manager for small teams. Built end-to-end on the MERN stack — no mock data, every click hits the API and is persisted in MongoDB.

![stack](https://img.shields.io/badge/stack-MongoDB%20·%20Express%20·%20React%20·%20Node-3d7bc4)

## Features

- **Auth** — register/login with JWT in HTTP-only cookies, bcrypt-hashed passwords, protected routes on both client and server
- **Tasks** — list, kanban board (drag & drop, persisted) and month calendar views; statuses (backlog → todo → in progress → review → completed), priorities, assignees, due dates, labels, subtasks and comments
- **Projects** — colored projects with progress stats, members, deadlines and a per-project activity feed
- **Workspaces & teams** — multi-workspace support, email invitations with shareable links, owner/admin/member roles
- **Inbox** — assignment, comment, status and deadline notifications (with light polling)
- **Dashboard** — live aggregates: status counts, overdue/due-today, 14-day completion chart (Recharts), upcoming deadlines and recent activity
- **Search** — ⌘K palette across tasks and projects
- **Settings** — profile & avatar upload (Multer, local disk), password change, per-type notification toggles, light/dark/system theme, soft account deletion

## Tech

| Layer | Choices |
| --- | --- |
| Frontend | React 19 + Vite, Tailwind CSS v4, React Router 7, Axios, dnd-kit, Recharts, Framer Motion, Lucide, react-hot-toast |
| Backend | Node + Express 5, Mongoose 8, JWT (httpOnly cookies), bcryptjs, Multer, express-validator, Helmet, rate limiting |
| Database | MongoDB Atlas |

Business logic lives in `server/services`, not routes. Errors are centralized, every list endpoint is paginated, and indexes back the hot queries.

## Getting started

```bash
# 1. Install everything
npm install            # root tooling (concurrently)
npm run install-all    # server + client dependencies
```

### Database

The app expects a MongoDB at `mongodb://127.0.0.1:27017/taskflow` (see `server/.env`).

**Easiest** — run the bundled starter (uses the portable MongoDB under `%USERPROFILE%\mongodb`):

```bat
start-mongodb.cmd
```

> The portable `mongod.exe` ships with the required VC++ runtime DLLs
> (`vcruntime140.dll`, `msvcp140.dll`, …) placed next to it in
> `%USERPROFILE%\mongodb\bin`, so no extra install is needed.
> To run MongoDB as a Windows service instead, install the official
> [MSI](https://www.mongodb.com/try/download/community) and it will start on its own.

**Or** point `server/.env` at any MongoDB you already have:

```
MONGO_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/taskflow
```

### Run it

```bash
# 2. Seed demo data (recommended the first time)
npm run seed

# 3. Run both halves
npm run dev
```

- API: http://localhost:5000 (proxied under `/api`)
- App: http://localhost:5173

### Optional: API smoke test

With the API running (and seed data loaded), exercise every major flow:

```bash
npm run smoke
```

## Project structure

```
server/
  config/         env + db connection
  controllers/   thin HTTP handlers
  services/       business logic (tasks, projects, invites, notifications…)
  models/         User, Workspace, WorkspaceMember, Project, Task,
                  Comment, Notification, Activity, Invitation
  routes/         mounted under /api
  middleware/     auth (JWT cookie), workspace access/roles, upload, errors
  validators/     express-validator schemas
  scripts/seed.js realistic demo dataset

client/
  src/
    components/   ui kit + feature components (tasks, projects)
    pages/        one per route
    layouts/      app shell, sidebar, topbar, search palette
    context/      auth, theme, workspace, refresh bus, notifications
    services/     one axios module per API area
    styles/       design tokens (CSS variables) + Tailwind v4
```

## Scripts

| Command | What it does |
| --- | --- |
| `start-mongodb.cmd` | starts the local portable MongoDB (Windows) |
| `npm run dev` | API (nodemon :5000) + web (vite :5173) together |
| `npm run seed` | wipes and reseeds the demo dataset |
| `npm run smoke` | end-to-end API smoke test against a running server |
| `npm run build` | production client bundle |
| `npm start` | production API only |

## Notes

- In development the Vite dev server proxies `/api` and `/uploads` to the API, so cookies stay same-origin — no CORS setup needed.
- Deadline notifications are generated by a sweep when the inbox is opened (no cron required).
- Deleting an account is a soft delete: tasks and comments keep a readable author.
